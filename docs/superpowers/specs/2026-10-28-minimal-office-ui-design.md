# Excel Sheet Merger — 미니멀 업무형 UI 디자인 명세

> 상태: 디자인 검토 요청 (구현 승인 전)  
> 작성일: 2026-10-28  
> 대상 저장소: https://github.com/sebia1993/Excel-Sheet-Merger  
> 기존 코드 기준: main commit 2f196bbf34e82c168123f19f7a2848b969ba5b6f  
> 플랫폼: Windows 11 x64 / Python 3.12 / Tkinter / PyInstaller

## 1. 목표와 배경

사용자는 정상 동작 중인 CSV → XLSX 자동 병합 기능을 **변경하지 않고**, 프로그램을 간결하면서 세련된 Windows 11용 업무 도구로 보이게 하려 한다. 선택된 시각 방향은 **A. 미니멀 업무형(화이트, 차콜, 차분한 그린)**.

성공 기준:
- 실행 후 3초 안에 어디서 폴더를 선택하고 다음에 무엇을 해야 하는지 파악할 수 있는 정보 구조.
- 파일 분류의 신뢰성(결과 파일명 / 원본 CSV / 시트 시간 / 제외 이유)이 미리보기에서 명확히 드러남.
- 진행 중, 건너뜀, 일부 실패, 완료가 색상 외에도 **텍스트**로 구분됨.
- 기존 CSV 병합, 원본 보존, 동시작업 제한, 실패 로그, EXE 배포 동작이 회귀하지 않음.

비목표:
- CSV 파서·파일명 패턴·시트 이름 부여 방식 변경.
- 드래그 앤 드롭, 대량 파일 검색의 재귀 스캔, 자동 덮어쓰기, 수식 변환, 다크 모드 신규 제공.
- 웹앱화 또는 Qt로의 프레임워크 전환.
- 브랜드 로고·상표 복제, 애니메이션 중심의 UI.

권장 기술 접근: **현존하는 MergeApp(tk.Tk)과 ttk.Treeview 및 이벤트 처리 코드를 유지**하면서, ttkbootstrap의 공용 Style을 적용하고 새로운 레이아웃·색상·간격을 입힌다. ttkbootstrap 최신 공개 릴리즈를 설계 시점에 v2.2.6으로 확인했으나, 구현 시 Python 3.12 및 PyInstaller와 호환되는 버전으로 명시적으로 고정하고 Windows CI에서 검증한다.

라이선스: 적용할 코드·소재는 MIT 조건을 준수하고 원 라이선스 고지를 검토한다. 다른 프로젝트의 스크린샷·로고·아이콘을 그대로 제품에 포함하지 않는다.

### 3.2 타이포그래피·간격·형태

- 기본 글꼴: 맑은 고딕(Malgun Gothic), Windows 폰트 폴백은 Segoe UI.
- 화면 제목: 20pt Bold; 섹션 제목: 11~12pt Semibold; 데이터: 10pt; 보조 문구: 9pt.
- 8px 간격 단위 중심: 8 / 16 / 24px; 카드 내부 16~20px.
- 기본 버튼 높이 38~42px. 하단 주 버튼 높이 44px.
- 아이콘 16~20px, 단색·일관된 스타일. 이모지 파일 아이콘은 교체. 외부 프로젝트 아이콘 무단 복사 금지.
- ttk 기반 표/프레임은 플랫폼별 둥근 모서리 구현이 제한적이므로 **얇은 경계·여백·선명한 타이포**를 우선한다. 둥근 모서리나 아크릴 효과는 필수가 아님.
- 창 기본 크기 1100×760, 최소 크기 900×640. 시스템 DPI 100/125/150%에서 줄바꿈·버튼 겹침·내용 잘림 점검.

## 4. 정보 구조 / 와이어프레임

1. 상단 헤더(약 66px): 아이콘 + **Excel Sheet Merger**, 설명 **CSV 파일을 시간별 시트로 자동 병합**; 우측 작은 “CSV → XLSX”.
2. **원본 폴더** 영역(약 90px): 현재 경로(읽기 전용), “폴더 선택” 보조 버튼, “파일 분석” 버튼. 원본 보존 안내문 1줄.
3. **분석 요약** 4칸(약 70px): 검색 파일 / 병합 그룹 / 단독 파일 / 인식 제외 파일. 기존 ScanReport 값을 그대로 사용한다. ‘검색 파일’에는 CSV가 아닌 지원 후보 확장자의 제외 대상도 포함될 수 있으므로 **검색한 CSV**라고 표현하지 않는다.
4. **병합 대상 미리보기** (가변 높이, 화면의 중심): 기존 계층형 Treeview 유지. 컬럼은 “결과 파일 / 항목”, “시트 이름 / 개수”, “원본 CSV / 사유”. 그룹은 굵은 글씨 또는 얇은 강조 배경, 하위는 들여쓰기. 단독/제외는 별도 트리 그룹으로 접을 수 있음. 하단에 선택 사용 안내: “파일 또는 하위 시트를 선택하면 해당 병합 그룹 전체가 선택됩니다.”
5. **작업 기록** 접힘 패널(기본 접힘, 펼침 시 최대 120px): 로그는 실행 중에도 내부적으로 유지; 실패 발생 시 자동 펼침. 파일로 저장하는 기존 동작 유지.
6. **하단 실행 영역** (약 100px): 좌측 진행률 및 텍스트 상태, 우측 “결과 폴더 열기” / “선택 그룹 병합” / **“전체 그룹 병합”**. 전체 그룹 병합만 짙은 녹색 배경과 흰색 텍스트.

### 화면별 문구

- 초기: “원본 CSV가 있는 폴더를 선택하세요.” / “파일을 분석하면 병합 결과와 시트 구성을 미리 확인할 수 있습니다.”
- 분석 완료: “병합할 그룹 2개 · CSV 6개를 확인했습니다.”
- 병합 대상 없음: “병합할 그룹이 없습니다. 제외 파일과 단독 파일을 확인하세요.”
- 작업 진행: “병합 진행 1/3 · A사업장_20261028.xlsx” (구현 시 이벤트 정보 접근 가능 범위에서 표기).
- 성공: “병합 완료 2개 · 실패 0개 · 건너뜀 0개”.
- 일부 실패: “병합 완료 1개 · 실패 1개 · 작업 기록을 확인하세요.”
- 기존 결과: “건너뜀: 같은 이름의 결과 파일이 이미 있습니다.” (기존 결과를 수정하지 않음).

## 5. 상태 전이와 상호작용

| 상태 | 기본 동작 | UI |
| --- | --- | --- |
| 폴더 미선택 | 분석/병합 불가 | 폴더 선택 강조, 병합 버튼 비활성 |
| 폴더 선택 + 분석 가능 | 선택 후 즉시 자동 분석하는 현재 동작 유지 | 미리보기와 요약 갱신 |
| 분석 결과 없음 | 병합할 그룹 없음 | 이유 안내, 그룹 병합 버튼 비활성 |
| 병합 그룹 있음 | 전체/선택 병합 제공 | 첫 번째 실행 버튼이 primary |
| 선택 그룹 없음 | 선택 병합 호출 시 기존 안내 표시 | 임의로 전체 그룹에 적용하지 않음 |
| 병합 실행 중 | 백그라운드 스레드/이벤트 큐 유지 | 폴더 선택·분석·병합 버튼 잠금, 결정형 진행률/상태 |
| 성공 | 기존 결과 폴더에 XLSX 및 로그 | 완료 메시지/결과 폴더 버튼 |
| 기존 파일 존재 | 덮어쓰지 않고 건너뜀 | 건너뜀 개수와 로그 표시 |
| 파일 실패 | 해당 그룹 실패 처리, 나머지는 계속 | 오류 텍스트와 상세 작업 기록 자동 펼침 |
| 닫기 시도(작업 중) | 기존 동작대로 종료 방지 | 사유 메시지 |

기존 Treeview의 하위 아이템을 선택할 때 해당 부모 그룹이 선택되는 규칙을 유지한다. 비동기 작업자는 tkinter 변수·위젯에 직접 접근하지 않는다. 진행 이벤트는 기존 큐를 통해 메인 UI 스레드로 전달한다.

## 6. 기존 기능에 대한 무변경 계약

- **변경 금지:** src/excel_sheet_merger/classify.py와 src/excel_sheet_merger/merge.py의 파일명 패턴, 정렬, CSV 인코딩 파싱, Excel 텍스트 처리, 출력 결과, 덮어쓰기 보호.
- **유지:** 원본 CSV 불변, 그룹당 2개 이상 CSV, 시간별 시트명(11시/14시/17시), 동일 시간 중복 시트명 처리, 제외/단독 항목 표시, 작업 로그 파일, 선택 병합, 진행 및 종료 보호.
- **편집 대상:** gui.py 중심의 레이아웃/색상/문구 변경; 선택적으로 ui_theme.py(스타일 분리), requirements-build.txt, 빌드 패키징 설정, GUI 스모크 테스트.
- **기존 인터페이스:** MergeApp, run_app, summarize_scan, _selected_groups, _start_merge, _worker_merge, _process_group, _consume_events의 기능 계약을 유지. GUI 테스트에서 __new__로 사용하는 _process_group 등은 호환성을 유지한다.
- Python/Excel 설치가 필요 없는 기존 Windows x64 EXE 배포 목표 유지.
- 네트워크 연결 및 외부 데이터 전송 기능을 추가하지 않는다.

## 7. 구현 검증(디자인 승인 후)

1. GUI 스타일 변경 전/후 기준 CSV 3개를 합쳐 “A사업장_20261028.xlsx”, 시트 “11시”, “14시”, “17시” 및 셀값 불변 검증.
2. 단독 파일, 제외 파일, 시간 중복, 기존 출력 충돌, UTF-8/CP949, 손상된 CSV, 일부 실패의 기존 테스트 전체 통과.
3. Windows 환경에서 GUI가 정상 생성·종료되고 미리보기 Treeview가 표시되는 스모크 테스트.
4. DPI 100/125/150%, 최소 900×640, 키보드 Tab 이동, 초점, 표 스크롤, 버튼 disabled 상태 수동 시각 검사.
5. PyInstaller Windows EXE 빌드, PE 헤더 확인, 파일 크기, 새 GUI 테마 자산 포함 확인.
6. 빌드가 성공하더라도 실제 Windows 11에서 실행해 병합까지 검증하기 전에는 **실사용 확인 완료**라고 주장하지 않는다.
7. 배포는 리뷰·테스트·사용자 디자인 승인 후 진행하며 기존 정상 릴리즈는 보존한다.

## 8. 디자인 검토가 필요한 판단

선택된 A 미니멀 업무형을 바탕으로 **ttkbootstrap + 단일 라이트 테마**를 1차 구현으로 권장한다. 다크 모드, drag-and-drop, 진짜 둥근 카드·투명 창 효과는 별도 개선으로 남긴다. 화면 모형과 이 문서를 사용자가 승인하기 전에는 실제 GUI 코드·EXE·릴리즈를 변경하지 않는다.
