# Excel Sheet Merger — 14차 안정성 재감사 (2026-10-29)

기준: v1.3.29 / `0f24e9348c87aa6f65667e92eb3742eb7de5d8a6`. 이번 범위: 정상 Excel 오탐의 일부를 안전 제한 안에서 개선. 8시간 Windows 장시간 시험은 최종 단계로 보류.

## 실제 문제와 최소 수정
고정 openpyxl 3.1.5는 `customXml/item1.xml`을 읽지 않지만 ZIP 사전검사에서는 모든 항목의 압축률을 보았다. 실제 XLSX에 160,013바이트/XML(압축 186바이트)을 넣고 테스트용 8KiB 임계값을 사용하니 기존 코드는 본문 데이터가 정상인데도 `압축 확장 비율` 오류로 중단됐다. 직접 openpyxl로 열면 셀 데이터를 읽을 수 있었다.

**수정:** 정확히 `customXml/item[1-9][0-9]*.xml`인 읽지 않는 부가 파일에만 압축률 휴리스틱을 적용하지 않는다. 모든 XML·ZIP 총량·구성 요소 개수·중복 검사, 나머지 모든 파일의 압축률 검사 및 원본 보호는 그대로 유지한다.

## 독립 실험 및 검증
- 실질적 RED→GREEN: 구버전 대상 신규 정상 고압축 부가 XML 테스트가 예상대로 예외로 실패, 수정 후 성공.
- 워크시트 XML 고압축 시 차단, 알 수 없는 부가 XML 차단, 부가 XML XML-용량 제한, 기존 69MiB comment-bomb 워크시트 차단을 회귀 검증했다.
- Linux/Python 3.13/Xvfb 전체 161개 실행, 157개 통과·Windows 전용 4개 제외, Python compileall 및 Git diff check 성공.
- 실제 비압축 69MiB / ZIP 내부 약 70KiB 비참조 부가 XML 샘플을 생성해 병합: 원본 Excel 셀과 수식, CSV의 00123, 출력 11시/14시를 확인. 이 추가 내용은 기존과 같이 결과에 복사되지 않는다.
- 이 환경에서 별도 회사 Windows PC의 8시간 검증은 실시하지 않았다. Windows 전체 CI/EXE 실행은 배포 후 확인한다.

## 안전상 유의사항
- 이번 변경은 ZIP/XML 크기 제한을 해제하는 것이 아니다. 기존보다 특정 무해한 부가 정보가 있는 문서는 더 많이 받아들이지만, 모든 압축 폭탄을 막는 절대 보증은 아니다.
- 높은 압축률의 실제 워크시트(정상 또는 비정상)는 기존 정책대로 차단된다. 무조건적인 완화는 메모리 폭증 위험이 있어 적용하지 않는다.
- 일부 Excel 차트·피벗·외부 링크·매크로는 원래도 완전 복사 대상이 아니며 그대로다.
- GUI 전체 로그 10만+ 건의 메모리 사용, 대형 SMB 파일 표본 밖 변경 감지, 실제 Windows 11·DRM·SMB·백신 8시간 시험은 추가로 남아 있다.
