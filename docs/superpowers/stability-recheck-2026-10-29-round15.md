# Excel Sheet Merger — 15차 안정성 재감사 (2026-10-29)

기준: GitHub v1.3.30 / `9df6226a560d13e85b21e35a565e5ce77aa1e5d4`; 정상 동작 보존 원칙. Windows 11 실PC 8시간 시험은 마지막 단계로 보류.

## 결함: 파일 분석 및 병합 시작 사이의 폴더 정규화 오류

`gui.py`의 `_scan()`은 `scan_folder()`에서 돌려받은 report를 `self.report`에 기록한 다음 별도의 보호 없이 `Path.resolve()`를 호출했다. 공유폴더 연결이 끊기는 등의 예외가 발생하면 반만 설정된 상태에서 GUI 콜백이 종료되었다. `_start_merge()` 역시 예외 처리 없이 `Path.resolve()`를 호출했으므로 이전 미리보기와 버튼 선택이 살아 있는 상태에서 GUI 예외가 발생할 수 있었다.

변경은 `_scan()`에서 스캔·정규화 모두 성공한 뒤 report를 확정하도록 하고, `_start_merge()`에서 OSError/RuntimeError 발생 시 기존 미리보기·체크 상태를 무효화하고 폴더 경로 및 조치를 안내한다. 정상 스캔 경로 또는 기존 병합 엔진의 처리 순서·파일 이름은 수정하지 않았다.

## 잔여 위험

1. 원본 파일 자체를 검사하는 동안 대규모 SMB 지연이 발생하면 현재 `_scan()`은 UI 스레드에서 실행되어 일시적으로 화면이 응답하지 않을 수 있다. 실제 응답시간을 측정한 후 구조 변경 여부 결정.
2. 로컬이 아닌 32MiB 초과 파일의 표본 밖 변경은 여전히 감지 불가능하다. SMB 읽기량과 정확도의 절충이 필요하다.
3. 실제 워크시트 XML의 정상적인 고압축 자료는 기존 안전 한도에 의해 거부될 수 있다. 무조건적인 완화 금지.
4. 복잡한 Excel 객체 및 10만 줄 이상 GUI 기록의 장시간 메모리 사용량은 독립적으로 검증해야 한다.
5. Windows 11·SMB·DRM·백신 환경의 8시간 실사용 시험은 최종 단계로 남긴다.
