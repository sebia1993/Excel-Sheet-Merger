# Excel Sheet Merger — 12차 안정성 재감사

기준 버전: v1.3.27 / `681d145bcc8d305742a14c01594535d197480e1d`.
범위: 기존 기능을 유지하는 GUI 오류 및 자원 소유권 수정. 8시간 장시간 시험은 마지막 단계로 유보.

## 실제 확인한 결함

1. Windows 기존 자동 테스트 150개가 통과해도 Tcl의 `unknown color name ""` 오류가 별도로 1회 발생했다. 분리된 진단은 Tk의 bgerror와 Python 콜백 예외를 수집해 이러한 숨은 실패를 검출했다.
2. 로그 영역의 세로 스크롤바만 생성하는 최소 사례에서 재현했다. 고정된 ttkbootstrap 2.2.6의 thumb field 요소가 focuswidth=0에서도 빈 focuscolor를 해석했다. 기존 팔레트의 유효한 색상을 지정하자 오류가 사라졌다.
3. MergeApp은 tk.Tk를 상속하므로 ttkbootstrap.App의 destroy 정리를 거치지 않았다. 같은 프로세스의 두 번째 창부터 theme_style.tk가 현재 app.tk와 다르고 닫힌 첫 창을 참조했다.
4. 테마 소유권을 수정하자 이전 테스트에서 가려졌던 최소 크기 오류 화면 문제가 드러났다. Windows에서 미리보기 높이 60px가 기존 기준 70px보다 작았다. 실패 문구를 줄이거나 테스트를 완화하지 않고 작은 창의 여백만 보정했다.

## 수정 경계

- ui_theme.py: Vertical.TScrollbar.focuscolor만 설정. root 자체의 Destroy 이벤트에서만 해당 root 소유의 Style.instance와 Fonts 캐시를 해제한다. 자식 위젯 삭제 또는 다른 root의 테마에는 적용하지 않는다.
- gui.py: 실패 안내가 있고 창 높이가 700px 미만일 때만 카드 여백을 최대 3px, 바깥 수직 여백을 5px로 조정한다. 정상 상태 및 창 확대 시 원래 여백을 복원한다. 오류 이유·조치·전체 로그·버튼은 유지한다.
- 병합·분류·파일 지문·저장·오류 진단·네트워크·압축 안전 모듈과 기존 테스트는 변경하지 않았다.
- 진단 전용 브랜치의 워크플로는 main에 포함하지 않는다. 새 프로세스로 실제 Tk를 구동하는 회귀 테스트만 제품 저장소에 유지한다.

- main 반영 후 Windows 전체 회귀 및 EXE 10회 스모크/Release는 해당 발행 커밋의 Actions로 별도 확인한다. 분리된 진단 성공을 EXE 배포 완료로 대체하지 않는다.

## 남은 한계 및 다음 판단

- 정상 고압축 Excel의 기존 안전 제한 오탐 가능성은 남아 있다. 이번 GUI 수정과 관련 없는 한도를 임의로 완화하지 않았다.
- 대형 네트워크 원본의 표본 밖 변경 감지 한계, 복잡한 Excel 객체 호환성, 전체 로그의 장시간 메모리 누적은 기존 범위의 한계다. 해결됐다고 주장하지 않는다.
- 최소 창 테스트는 명시한 폰트·화면 배율·실패 안내로 수행했다. 모든 Windows DPI 및 임의로 긴 파일명/오류 문구에 대한 보장은 아니며 최종 실PC 검증에서 점검한다.
- litera 테마의 향후 버전 폐기 경고는 남아 있다. 현재 고정 버전에서는 동작하며, 디자인 유지를 위해 테마를 교체하지 않았다.
- 짧은 합성 테스트와 hosted Windows Server 2025 진단은 회사 Windows 11·DRM·SMB·백신 환경의 8시간 실사용 검증을 대신하지 않는다. 그 시험은 아직 시작하지 않았다.
