# Excel Sheet Merger — 4차 안정성 개선 및 추가 감사

일자: 2026-10-28. 기준 소스: GitHub v1.3.16의 `45a70d7b74b7b46c4187a9091ca8500b6d0b751a`와 Git blob 해시가 동일한 로컬 통합 작업본. 배포 버전은 GitHub Actions 완료 확인 후 별도 기록.

## 이번에 수정·검증한 범위

1. **임시 ZIP 공간 예측:** 혼합 CSV+Excel 그룹은 임시 `base.xlsx`·`csv.xlsx`를 저장한 다음 결과 드라이브의 여유 공간을 확인. 두 압축 파일 크기 합계 + 최대(합계 10%, 1MiB)를 안전 여유 공간 *추정치*로 사용한다. 사용 가능 공간이 명백히 작으면 최종 ZIP 작성 전에 `ENOSPC` 예외를 발생시키고 개인 임시 폴더를 정리한다. 실제 공간 예약은 아님; 별도 프로세스·압축률·서버 할당량으로 실패할 수 있다.
2. **SMB 조회 오류 호환성:** `shutil.disk_usage(output_dir)`이 `OSError`로 실패하는 환경에서는 해당 추정을 건너뛰고 기존의 안전한 쓰기/원자적 게시 흐름을 유지한다. 특정 서버가 부정확한 용량을 보고할 가능성은 남는다.
3. **사용자 오류 분류:** 운영체제 `ENOSPC`, `EDQUOT` 및 `SourceFileError`에 감싸진 동일 코드의 예외를 `DISK_FULL`로 안내하고, 회사 공유폴더 할당량 및 로컬 결과 드라이브 용량을 확인하도록 설명한다. CSV 인코딩/DRM 오류는 그대로 분리한다.
4. **충분한 공간/쓰기 중 소진/CSV 전용:** 정상 워크북 시트·수식·문자 값과 기존 결과 불변성·임시 폴더 정리·CSV-only 처리 원칙을 테스트로 검증한다.
5. **GUI 기록 보존:** 화면에서 2만 건의 인공 로그 메시지를 렌더링하고 모든 메시지와 순서가 보존됨을 확인. UI의 과거 로그를 자르거나 삭제하는 행동 변경은 하지 않았다.

## Linux 합성 측정 (테스트 조건 한정)

- Python 3.13 / Linux Xvfb / 2만 행 CSV와 단일 시트 XLSX: 최종 ZIP 생성 직후 `base.xlsx` 5,278바이트, `csv.xlsx` 396,640바이트, `result.xlsx` 396,856바이트. **이 세 압축 파일의 합계 약 798,774바이트**는 이 시점의 개인 scratch 폴더 규모를 추정하는 참고치. openpyxl 내부 임시 XML, OS 캐시, 다른 사용자 프로세스 저장 공간은 포함되지 않는다.
- Tkinter GUI 로그 **20,000건** 합성 이벤트: 200번 이벤트 처리 호출, 0.42초, Python tracemalloc 최대 2.93MiB, 프로세스 RSS 최대 메모리 125.7MiB → 136.6MiB(최고 기록 값), 화면 약 98만 글자. 성능 수치는 호스트와 메시지 길이에 크게 의존한다.
- 기존 91개 회귀 테스트에서 디스크 보호 5개 + 오류 안내 2개 + 대량 로그 표시 1개를 추가해 **99개 테스트 통과**(Linux Xvfb, 5.28초). 실제 8시간 실행은 하지 않았음.

## 재감사: 추가 개선 후보 및 보류 사유

| 우선순위 | 항목 | 판단/다음 단계 |
|---|---|---|
| P1 | 회사 Windows 11 + DRM/SMB/백신의 8시간 운영 | 실제 승인된 PC에서 장시간 무결성·메모리·핸들·용량 테스트 필요. 호스팅 Windows CI로 정책 재현 불가 |
| P2 | 임시 ZIP 공간 예측의 부정확성 | 공유폴더 서버 할당량, 다른 작업과 동시 저장, 압축률 변화는 예측 불가. 실제 업무파일에서 계측하고 보수적 정책 검토 |
| P2 | 대형 입력(8MiB 이상)의 부분 지문 검사 | 표본 밖 변경은 감지 불가. 원본 전체 해시 또는 중간 스냅샷 비용을 SMB 환경에서 평가 |
| P2 | 복잡한 Excel 형식 호환성 | 수식 캐시/피벗·이미지·차트 등은 완전 보존 범위 밖. 허가된 실파일로 수동 검증 |
| P3 | GUI 작업 기록의 무한 누적 | 2만 건에서 최대 RSS +약 11MiB 확인. 과거 로그 자동 삭제는 UI 동작 변경이므로 이번에는 미적용. 가상화·전체 기록 접근 설계 필요 |
| P3 | PyInstaller 강제 종료 시 `_MEI*` | 사용 중 프로세스와 소유권 구분 없이 임시 경로 삭제하지 말 것. 실제 Windows에서 검증 |
