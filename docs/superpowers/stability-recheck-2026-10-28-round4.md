# Excel Sheet Merger — 안정성 재감사 5차 (대용량 원본 지문)

기준: GitHub Release v1.3.17 (`2a65c94dc1a2b49034df2d6d29ef0e7aaa26eb10`) 소스와 Git blob 동일한 로컬 작업본. 사용자 기능/UX 변경 없음.

## 재현 원인과 수정 사항

- 기존 `classify.file_fingerprint()`는 8MiB 초과 파일의 3개 창(맨 앞/중간/끝 각각 64KiB)만 읽었다. 17MiB 합성 원본의 25%·75%를 동일 크기로 수정하고 원래 수정시각을 복원하면 `_verify_source()`는 변경을 놓쳤다. 신규 테스트는 이전 코드에서 정확히 세 건 실패한 것을 확인했다.
- 변경 후 17개 균등 간격 창(첫 번째와 마지막 포함, 각각 64KiB), BLAKE2b 위치+데이터 지문을 이용한다. 원본 변경 감지 테스트 3개와 기존 테스트 모두 통과. 파일명 분류와 CSV/Excel 변환, 로그, GUI, 결과 파일명 번호 규칙은 그대로 유지한다.
- 읽는 데이터는 큰 파일당 검사 1회에 **1,088 KiB**(17 × 64KiB)로 제한된다. 8MiB 이하 전체 읽기 유지. 새로운 Python 의존성 없음.

## 측정: 로컬 Linux 파일 시스템, Python 3.13, 합성 128MiB

- 3창: 192KiB, 중앙값 0.0003초.
- 17창: 1088KiB, 중앙값 0.0016초.
- 전체 해시: 128MiB, 중앙값 0.1847초.
- 실사용 SMB에서는 네트워크 레이턴시, 보안 필터, 파일 캐시 때문에 17회 임의 접근 비용이 달라질 수 있다. 이 테스트로 기업 네트워크 성능이나 보안성 보장은 불가능하다.

- [x] 크기·수정시각 동일한 대형 파일의 25%/75% 변경을 탐지한다.
- [x] 17회의 64KiB 읽기 상한을 자동 테스트로 고정한다.
- [x] 정상 CSV/Excel 워크북의 값·수식·시트명·체크박스·원본 보존 회귀 테스트 실행.
- [x] Linux Xvfb 102개 테스트 통과, 문법 검사 및 ZIP 규칙 확인.
- [ ] 정확한 SHA의 Windows CI, 실제 패키징 EXE 및 GitHub Release는 원격 빌드 결과 확인 후 표기한다.

## 새로 확인한 잔여 위험 및 다음 개선 권장 순서

1. **P1 실환경 필수:** 기업 Windows 11 + DRM/SMB/백신 권한과 8시간 장시간 검증은 GitHub CI로 재현할 수 없다. 회사 승인이 있는 테스트 PC와 익명화된 샘플이 필요하다.
2. **P2 완전성 공백:** 17개 표본 창 밖 변경은 여전히 검출하지 못한다. 전체 해시 옵션은 SMB I/O와 동기 파일 분석 UI의 응답 시간을 악화할 수 있으므로 실제 네트워크 측정 전 강제 도입하지 않는다.
3. **P2 경로 변동:** SMB 드라이브에서 파일이 재연결되거나 작업 중 연결이 끊기면 OS 오류로 실패 처리하고 기존 결과를 보존하지만, 네트워크 재연결 자동 재시도는 하지 않는다(데이터 일관성 위험).
4. **P2 복잡한 Excel:** 피벗, 차트, 그림, 수식 캐시 등은 기본 셀/서식 복사의 충실성 범위를 벗어날 수 있다. 업무 파일로 직접 Excel에서 확인해야 한다.
5. **P3 장시간 로그:** 현재 GUI는 모든 로그를 표시하고 메모리에 보존한다. 로그 자동 삭제는 행동 변경이므로 미적용; 로그 가상화는 사용성 승인 및 설계 검토 후 도입한다.
6. **P3 단일 EXE 강제 종료:** PyInstaller `_MEI*` 임시 추출 폴더가 남을 수 있다. 소유권이 없는 다른 프로그램 파일을 자동 삭제하지 않는다.

선택한 대응은 작업 안전성을 높이면서도 기존 사용자 기능을 유지하는 범위다. 이 감사만으로 100% 데이터 위변조 탐지를 주장하지 않는다.
