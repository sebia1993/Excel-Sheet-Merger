# Excel Sheet Merger — 16차 안정성 재감사 (2026-10-29)

기준: GitHub v1.3.31 / `bf549e4f34774a1998e27978d067d256a24350b7`.

## 재현 결함

`scan_folder`은 결과 파일명을 `_safe_filename(site + '_' + date) + '.xlsx'`로 설정했다. `_safe_filename`이 150자로 무조건 잘라 사업장명이 긴 경우 날짜가 소실됐으며, 서로 다른 날짜 또는 서로 다른 긴 사업장명끼리 결과명이 겹쳐 안전 중복 검사에서 전체 스캔을 중단했다. 원본 파일 자체는 Windows/리눅스에서 유효한 170자 내외 ASCII 파일명을 사용해 문제를 재현했다.

## 제한적 개선

- 출력명 전체가 150자 이내여서 날짜 `_YYYYMMDD`가 유지되면 기존 이름 그대로 사용.
- 날짜가 잘리는 긴 사업장은 출력명 끝에 `~` + BLAKE2b 12자리(site 전체) + `_YYYYMMDD`를 남기고 앞쪽 사업장명을 축약.
- 이미 존재하는 서로 다른 그룹 결과명 중복 검증은 계속 수행하고, 기존 결과 보호·(2)·(3) 자동 부여는 유지.
- 시간별 시트, CSV 숫자 문자열 00123, 원본 보호, GUI 체크박스와 데이터 처리 엔진은 변경하지 않음.

## 테스트 증거

- RED: 다른 날짜의 긴 사업장 이름으로 생성한 CSV 4개, 같은 150자 접두사를 갖는 사업장 2곳의 CSV 4개 모두 기존 코드에서 `서로 다른 그룹의 결과 파일명이 중복됩니다` 예외 재현.
- GREEN: 2개 테스트 모두 통과. 날짜와 해시 구분, 두 개의 독립 결과 XLSX와 시트 내용, 기존 이름 정책 유지 확인.
- 전체 Linux/Python3.13/Xvfb 테스트 166개 실행, 162개 통과·Windows 전용 4개 제외. `compileall`과 CRLF-aware `git diff --check` 통과.
- Windows Actions와 패키징 EXE 반복 병합 검증은 Release 발행과 함께 별도 확인. 실제 회사 PC 8시간 시험은 실행하지 않음.

## 잔여 개선 후보

- 사업장명에 경로와 운영체제별 이례적 Unicode 정규화가 혼합된 경우의 경로 충돌은 추가 테스트 대상.
- 공유폴더 파일 분석은 현재 UI 메인 스레드에서 실행되므로 수천 개 파일/높은 SMB 지연에서는 응답성 저하 가능성.
- 기존 정상 고압축 워크시트의 ZIP 안전 제한 오탐, 특수 Excel 객체 호환성, 네트워크 표본 밖 변경 감지, GUI 10만 행 이상 로그 메모리 증가도 추가 확인 대상.
- Windows 11·SMB·DRM·백신 8시간 장시간 실사용 시험은 최종 단계 보류.
