# Excel Sheet Merger — CSV·Excel → XLSX 시간별 시트 자동 병합

Windows 11용 한국어 GUI 프로그램입니다. 같은 **사업장 + 날짜**의 여러 CSV·Excel 파일(`.csv`, `.xlsx`, `.xlsm`, `.xls`)을 하나의 `.xlsx` 파일로 합치고, **원본 파일명 속 시간**을 시트 이름으로 사용합니다. CSV와 Excel 파일이 섞여 있어도 병합할 수 있습니다.

**Python 설치도, Microsoft Excel 설치도 필요하지 않습니다.** 실행 파일은 Python/Tkinter, ttkbootstrap, openpyxl, xlrd를 PyInstaller로 패키징합니다.

## v1.2 미니멀 업무형 화면

화이트/그린 컬러의 Windows 11 업무 도구 스타일을 적용했습니다. 기존 v1.2 디자인을 유지한 채 Excel 입력 지원을 추가했습니다. CSV 텍스트 처리와 기존 파일 보호 방식은 그대로입니다.

- 상단: **폴더 선택 → 파일 분석**. 선택하면 기존처럼 즉시 분석합니다.
- 요약 카드: **검색 파일 / 병합 그룹 / 단독 파일 / 제외 파일** 개수.
- 가운데: 넓은 계층형 **미리보기 표**. 병합 가능한 **그룹 행마다 ☐/☑ 체크박스**가 표시됩니다. 하위 시간별 시트는 내용 확인용이며, 체크 대상이 아닙니다.
- 그룹 선택: `전체 선택`, `선택 해제` 버튼 또는 그룹 행 클릭으로 복수 그룹을 체크할 수 있습니다. 키보드로 그룹 행에 포커스한 뒤 `Space`를 눌러도 체크가 전환됩니다. 왼쪽 펼침 화살표는 체크 상태를 변경하지 않습니다.
- 하단: **전체 그룹 병합**(녹색 주 버튼)은 체크 여부와 관계없이 모든 병합 가능 그룹을 처리합니다. **선택 그룹 병합**은 체크된 그룹만 처리하며, 체크가 없으면 비활성화됩니다. 기존 **결과 폴더 열기** 및 진행률도 유지합니다.
- **작업 기록 보기**는 기본으로 접혀 있습니다. 오류가 발생하면 자동으로 펼쳐지고, 화면에 **문제 파일·원인·조치 방법 안내**가 남습니다. 완료 안내창에서도 파일별 설명을 확인할 수 있습니다.
- 앱은 한국어 UI입니다. 기존 결과를 덮어쓰지 않으며, **같은 파일명이 이미 있으면 `(2)`, `(3)`...을 붙여 새 파일을 생성**합니다. CSV 텍스트 값은 변경 없이 보존합니다.

UI는 [ttkbootstrap](https://github.com/israel-dryer/ttkbootstrap)(MIT)의 기존 ttk 스타일 확장을 이용합니다. 실제 사용자는 별도 테마나 라이브러리를 설치하지 않아도 됩니다. Windows의 접근성 배율(100~150%) 및 실제 창 크기는 사용 PC에서 확인해 주세요.

## 병합 결과 예시

| 원본 파일 | 병합 결과 | 시트 이름 |
| --- | --- | --- |
| `A사업장_20261028_11시.csv` | `A사업장_20261028.xlsx` | `11시` |
| `A사업장_20261028_14시.xlsx` | `A사업장_20261028.xlsx` | `14시` |
| `A사업장_20261028_17시.xls` | `A사업장_20261028.xlsx` | `17시` |

CSV만 3개, Excel만 3개, 또는 **CSV와 Excel이 섞인 3개**도 모두 같은 방식으로 병합합니다. 결과 파일은 선택 폴더 아래 `병합결과`에 저장합니다. 사업장이나 날짜가 다르면 별도 파일로 만듭니다.

## EXE 사용 방법

1. [최신 Windows EXE 다운로드](https://github.com/sebia1993/Excel-Sheet-Merger/releases/latest/download/ExcelSheetMerger.exe) → **Assets**에서 `ExcelSheetMerger.exe`를 받습니다.
2. Windows 11에서 실행 후 **폴더 선택** → CSV·Excel 파일이 담긴 폴더 지정.
3. **파일 분석**으로 그룹, 결과 파일명, `11시` / `14시` / `17시` 시트명, 제외 사유를 미리 확인합니다.
4. 일부 그룹만 병합하려면 그룹 행의 **☐ 체크박스**를 선택하고 **선택 그룹 병합**을 클릭하세요. 모두 병합하려면 체크 여부와 관계없이 **전체 그룹 병합**을 클릭합니다.
5. `병합결과` 폴더에서 `.xlsx` 파일과 UTF-8 작업 기록을 확인합니다. 동일한 결과 파일명이 이미 있으면 완료 창에 안내가 나타나고 기존 파일명 → 새 파일명이 기록됩니다. **병합 실패가 발생하면 파일명·가능한 원인·조치 방법을 프로그램 내 알림과 실패 팝업에서 확인**할 수 있습니다. 기존 TXT 작업 기록에는 자세한 기술 오류도 남습니다.

## 지원 형식과 제한 사항

- **지원 입력:** `.csv`, `.xlsx`, `.xlsm`, `.xls` (대소문자 구분 없음). `.xlsb` 등 다른 형식은 인식 제외 사유를 표시합니다.
- 일반 Excel은 **원본 파일당 시트가 정확히 1개**여야 합니다. 원본에 여러 시트가 있거나 파일이 손상된 경우 해당 **그룹 전체**를 실패 처리하고 다른 그룹 처리는 계속합니다.
- 날짜: `20261028`, `2026-10-28`, `2026_10_28`, `2026.10.28`.
- 시간: `11시`, `09시30분`, `14-30`, `1430`, `오전9시`, `오후2시` 등.
- 파일명에서 날짜 **하나**와 시간 **하나**를 인식할 수 있어야 하며, `최종`, `수정` 같은 접미사는 사업장 구분에 포함됩니다. 비슷하지만 다른 이름의 파일을 임의로 합치지 않습니다.
- 사업장명과 날짜가 동일한 파일을 묶고 시간을 오름차순 정렬합니다. 같은 시간에 원본이 2개 있으면 `11시`, `11시 (2)`로 이름을 구분합니다. 단독 파일 1개 그룹은 병합 보류합니다.
- CSV는 **UTF-8(BOM 포함), CP949/EUC-KR, UTF-16(BOM)** 등을 처리하며 쉼표·쌍따옴표·줄바꿈을 지원합니다. CSV의 모든 값은 **Excel 텍스트**로 저장해 `00123`, IP/MAC, `=SUM(...)` 같은 문자열이 자동 변환되지 않게 합니다.
- `.xlsx`·`.xlsm`은 숫자/날짜/문자열/수식/대표 셀 스타일·셀 병합·행/열 크기·틀고정을 가능한 범위에서 보존합니다. **차트·이미지·피벗 테이블·외부 연결·조건부 서식·수식 캐시는 완전 복제를 보장하지 않습니다.** 수식 중 원본 시트명을 직접 참조하는 수식은 시트명이 바뀌므로 사용자가 결과를 검증해야 합니다.
- `.xlsm`을 `.xlsx`로 변환할 때 매크로(VBA)는 제거됩니다. `.xls`는 **셀 값·날짜·불리언** 중심으로 변환하며 기존 셀 서식은 복사하지 않습니다. 기존 xls 수식은 마지막으로 계산된 값으로 읽힐 수 있습니다.
- **원본 CSV/Excel 파일은 수정하지 않습니다.** 결과 파일명이 중복되면 기존 결과를 덮어쓰지 않고 새 파일을 추가로 생성합니다. 예: `A사업장_20261028.xlsx` → `A사업장_20261028 (2).xlsx` → `A사업장_20261028 (3).xlsx`. 번호는 사용되지 않은 가장 작은 값부터 부여합니다.
- 이름 충돌은 GUI의 작업 기록과 완료 안내에 표시됩니다. 작업 기록에는 **원래 파일명 → 실제 생성 파일명**이 남습니다. 생성 중 오류가 나면 임시 출력 파일을 지웁니다. 다른 프로세스가 같은 이름을 동시에 생성해도 파일을 덮어쓰지 않고 다음 번호를 시도합니다.
- Excel 한계: 시트당 **1,048,576행 × 16,384열**. Excel 포함 그룹은 서식을 복사하기 위해 메모리를 더 사용하므로 대형 Excel 파일에서는 메모리 부족에 유의하세요.
- **Excel 설치가 필요하지 않습니다.** 완성된 XLSX를 열려면 Excel 또는 호환 뷰어가 필요합니다.

## 파일 병합 실패 시 프로그램 내 원인 안내

병합에 실패한 그룹은 원본 전체를 변경하지 않고 실패 처리하며 다른 그룹은 계속 병합합니다. 실패 파일별 안내를 **프로그램 하단 오류 배너 / 완료 팝업 / 자동으로 펼쳐진 작업 기록**에서 확인할 수 있습니다. 안내에는 원본 파일명, 이해하기 쉬운 원인, 권장 조치가 표시됩니다. 작업 기록에는 기술적 오류 내용도 별도로 유지합니다. 새로 파일 분석·병합을 시작하면 이전 실패 안내는 초기화됩니다.

특히 `cp949 codec can't decode ...` 또는 `CSV 문자 인코딩 오류`는 **파일 내용이 CP949 문자 인코딩으로 해석되지 않는다**는 뜻입니다. 회사 문서보안 프로그램에 의해 보호된 문서에서 나타날 수 있지만, 실제로는 손상된 파일이나 다른 인코딩/파일 형식일 수도 있습니다. **이 오류만으로 암호화 여부를 판정하거나 자동으로 암호 해제하지 않습니다.** 회사 보안 정책을 준수하여 권한이 부여된 프로그램에서 정상적으로 열거나 CSV/Excel 내보내기가 허용되는지 확인한 뒤 재시도하세요. 문서보안 설정으로 열람·내보내기가 제한된다면 보안 담당자에게 문의하세요.

추가로 파일 누락, 접근 권한 부족, CSV 따옴표 구조 오류, 빈 원본, Excel 다중 시트/형식 문제 등에 대해 조치 안내를 제공합니다. 알 수 없는 오류는 임의로 암호화라고 판단하지 않고 작업 기록을 담당자에게 전달하도록 안내합니다.

## 자동 EXE 빌드 및 Release

`main` 브랜치에 변경이 푸시되면 `.github/workflows/windows-exe.yml`이 Windows 러너에서 **테스트 → PyInstaller EXE 빌드 → PE 형식 검사 → SHA-256 생성 → GitHub Release 업로드**를 수행합니다. 성공 이후 [Releases](https://github.com/sebia1993/Excel-Sheet-Merger/releases/latest)에서 버전별 다운로드를 확인할 수 있습니다. 혼합 입력 지원 버전은 `v1.3.<워크플로 실행 번호>` 태그로 배포됩니다.

개발 PC에 Python 3.12가 설치되어 있다면 `build_windows.bat`로 로컬 빌드할 수 있습니다. 사용자 PC에는 Python을 설치할 필요가 없습니다.

## 개발과 테스트

- Python 3.12+, `openpyxl>=3.1.5`, `xlrd==2.0.2`, Tkinter, `ttkbootstrap==2.2.6`, PyInstaller.
- `python -m pip install -r requirements-build.txt` (개발/빌드 PC만)
- `python -m unittest discover -s tests -v`
- `python app.py`
- 주요 파일: `src/excel_sheet_merger/classify.py`(파일명 분류), `merge.py`(CSV·Excel 입력 및 XLSX 생성), `gui.py`(한국어 GUI), `ui_theme.py`(UI 디자인 토큰).

## 실제 환경 검증 범위

CSV·XLSX·XLSM 변환은 테스트 워크북으로 검증합니다. `.xls`는 테스트용 읽기 인터페이스를 통해 동작을 검증하되 실제 구형 Excel 파일에 대한 추가 실사용 테스트를 권장합니다. GitHub Actions에서 Windows용 EXE 패키징도 확인할 수 있습니다. **실제 회사 PC/VDI 정책, 백신 탐지, 특수 CSV 인코딩 및 대용량 처리**는 실사용 환경에서 추가 검증이 필요합니다. 코드 서명되지 않은 EXE는 회사 보안정책상 실행 제한될 수 있으니 정책을 준수하세요. Linux에서는 ttkbootstrap 설치가 불가능할 때 개발용 `clam` 스타일로 UI 스모크 테스트를 할 수 있지만, **Windows 릴리즈는 ttkbootstrap을 반드시 설치하고 포함**합니다.


## 안정성 보강 (기존 사용법 및 화면 변경 없음)

- 폴더 분석 도중 접근 오류가 발생하면 이전 폴더의 병합 목록이 재사용되지 않도록 상태를 초기화합니다. 재분석 후 병합을 실행하세요.
- 분석 이후 파일이 변경·교체되거나 병합 중 변경된 경우 불완전한 결과를 생성하지 않고 해당 그룹에 오류를 표시합니다. 공유폴더에서 파일 갱신이 끝난 뒤 다시 파일 분석을 해주세요.
- CSV+Excel 혼합 그룹도 CSV 부분을 스트리밍 처리하여 대용량 처리 메모리 사용을 줄였으며, Excel의 값·수식·서식·병합 셀은 기존대로 유지합니다.
- 임시 XLSX는 OS 잠금이 적용된 전용 작업 폴더에 만들고, 정상 종료 시 삭제합니다. **24시간 이상 지난 잔여 폴더만** 정확한 식별 정보와 잠금 해제 여부를 확인해 다음 실행 시 정리합니다. 실행 중인 다른 작업과 소유권 불명 파일은 건드리지 않습니다. 구버전의 `_병합중_*.xlsx` 임시 파일은 안전을 위해 자동 삭제하지 않습니다.
- 작업 기록 TXT는 완성된 내용을 원자적으로 게시합니다. 기록 저장이 실패하면 XLSX 생성 성공과 별도로 경고를 표시합니다.
- GUI 이벤트는 여러 번 나누어 처리해 대량 작업에서도 프리뷰 응답성을 보호합니다.
- Windows 빌드는 검증된 버전의 의존성을 사용하고, 패키징된 **실제 EXE**에서 CSV+XLSX 병합을 실행하는 자동 스모크 검사를 통과해야 릴리즈됩니다.
- PyInstaller onefile이 강제 종료되면서 남긴 `_MEI*` 파일은 안전하게 자동 삭제하지 않습니다. 회사 정책이 허용하는 범위에서 Windows TEMP 상태를 점검하세요.



## 안정성 후속 검증 — 혼합 파일 ZIP 재압축

- CSV·Excel 혼합 병합의 임시 ZIP 재압축 중 **CSV 시트 XML만 압축 부담을 조정**했습니다. Excel 시트, 수식·스타일, 원본 CSV 텍스트, 결과 이름 및 GUI 동작은 동일합니다.
- ZIP CRC·워크북 열기·수식·텍스트 보존 검증과 **연속 혼합 병합 100회** 회귀 테스트를 추가했습니다. 기존 출력 파일 덮어쓰기와 임시 폴더 잔존도 검사합니다.

## 원본 내용 검증 보강 (v1.3.15 이후)

- 파일 분석에서 **크기·수정시각·식별자 외에 원본 데이터 지문**도 기록해 파일 변경을 더 정확하게 확인합니다.

- 파일 검증을 위한 읽기 작업으로 일부 대용량/네트워크 공유폴더에서는 분석·병합 시간이 늘 수 있습니다. 대형 파일의 완전 무결성 확인이 필요하면 별도 전체 해시 검증이 필요합니다.
- Windows CI에서 패키징된 EXE의 샘플 병합 테스트를 **3회에서 10회**로 늘려 배포 패키지의 반복 실행을 확인합니다. 회사 DRM·SMB·백신 환경 테스트를 대신하지는 않습니다.


## 저장 공간 부족 대응 / 장시간 작업 기록 검증 (안정성 후속)

- CSV와 Excel이 섞인 병합에서 `base.xlsx`와 `csv.xlsx` 두 임시 압축 파일을 만든 뒤 **병합결과가 저장되는 실제 드라이브의 여유 공간**을 확인합니다. 계산된 예상 여유 공간보다 부족하면 최종 ZIP 작성 전에 중단해 기존 파일을 보호하고 임시 작업 폴더를 정리합니다. **예상치는 예약이나 보증이 아니므로** 동시 작업·네트워크 공유폴더 할당량·압축률 변화로 작성 중 공간 부족이 생길 수 있습니다.
- `ENOSPC`(디스크 공간 부족)와 `EDQUOT`(파일시스템 할당량 초과) 오류는 프로그램에서 저장 공간 및 공유폴더 할당량을 확인하라는 **한국어 안내**로 구분됩니다. 공유폴더에서 여유 공간 정보를 조회할 수 없는 경우 이전과 같이 실제 쓰기 결과로 판단합니다.
- CSV만 있는 그룹은 기존 처리 경로가 그대로 유지됩니다. 결과 파일명 `(2)`·`(3)` 및 Excel 데이터·수식·서식 규칙도 유지됩니다.
- `xvfb-run -a env PYTHONPATH=src python benchmarks/measure_round3_resources.py`로 합성 2만 행 혼합 파일의 임시 ZIP 사용량 및 GUI 작업 기록 2만 건의 메모리·시간을 측정할 수 있습니다. GUI 작업 기록은 **삭제하거나 잘라내지 않고 그대로 보존**합니다. 장시간 메모리 증가는 남은 개선 검토 대상이며, 회사 Windows 11/DRM/SMB에서 8시간 검증은 별도로 수행해야 합니다.

## 로컬 디스크 원본 변경 검사 안정성 강화 (v1.3.19 이후)

- 기존 **8MiB 이하 원본 전체 검사**는 유지합니다. Windows에서 확실하게 확인된 **고정 로컬 디스크의 8~32MiB 원본**도 이제 128KiB 스트리밍으로 전체 내용을 검사합니다. 크기·수정시각은 같지만 이전 17구간 표본 사이에서 내용이 바뀐 경우도 감지할 수 있습니다.
- 네트워크 연결 드라이브(SMB 매핑 포함), UNC 공유폴더, 드라이브 유형을 확인할 수 없는 경로 및 32MiB 초과 원본은 **17구간 × 64KiB** 표본 검사를 유지합니다. 공유폴더에 대한 대량 재읽기를 피하기 위한 보수적 정책입니다. 작은 파일은 드라이브 종류에 관계없이 기존처럼 전체를 검사합니다.
- 표본 밖 변경은 여전히 감지되지 않을 수 있으며, 검사는 원본을 수정하거나 DRM을 우회하지 않습니다. Linux 개발 환경과 실제 회사 Windows 공유폴더의 I/O 성능은 동일하지 않습니다.

## Windows 실사용 전 안정성 보강 — 정션 경로와 결과 폴더 오류

- Windows 로컬 드라이브로 보이는 경로라도 **상위 폴더가 정션·심볼릭 링크·클라우드 재분석 지점**이면 대형 원본 파일에 대한 전체 해시를 시도하지 않고, 기존 17구간의 제한된 표본 검사로 전환합니다. 이를 통해 네트워크 연결 위치가 로컬 드라이브 아래에 연결된 경우 불필요한 공유폴더 읽기를 줄입니다. 표본 밖 변경 감지 한계는 그대로입니다.
- `결과 폴더 열기` 버튼을 눌렀을 때 권한 부족이나 공유폴더 접속 오류가 발생하면, 프로그램 화면에 경로·가능한 원인·조치 방법을 안내합니다. 성공 시 폴더 생성과 탐색기 열기 동작은 기존과 같습니다.
- **8시간 장시간 Windows 검증은 마지막 단계로 보류**합니다. 실제 회사 DRM·SMB·백신 환경의 안전한 샘플로 Codex에서 실행할 예정이며, 해당 실기기 검증을 완료했다고 주장하지 않습니다.


## Excel 압축 파일 비정상 확장 방지 (안정성 보강)

- XLSX/XLSM 원본을 읽기 전에 ZIP 구성요소의 **압축 해제 예정 크기와 비정상적인 압축 비율**을 검사합니다. 매우 작아 보이는 파일도 압축 해제 시 대량 메모리를 차지할 수 있기 때문입니다.
- ZIP 항목 30,000개 초과, 전체 압축 해제 크기 1GiB 초과, 단일 XML 구성요소 256MiB 초과, 또는 64MiB 초과 ZIP 구성요소의 압축 확장 비율이 400배를 넘는 경우 작업 안전을 위해 해당 그룹을 중단합니다. ZIP 내부 경로가 중복돼도 거부합니다.
- 정상 Excel 파일의 수식·서식·셀 복사 및 CSV 텍스트 처리, 번호 붙인 결과 파일명 규칙은 유지합니다. 이미 존재하는 결과 및 원본 파일은 변경하지 않습니다.
- 위 한도에 해당하는 **정상적인 초대형·고압축 문서**도 안전을 위해 거부될 수 있습니다. 이 경우 회사에서 승인된 Excel에서 문서를 확인하고 별도 정상 문서로 저장하여 다시 분석하세요. 암호화나 악성 여부를 단정하는 기능은 아닙니다.
- 이는 ZIP 메타데이터 기반 사전 제한으로, 원본 파일이 안전하다는 보증이나 바이러스 검사가 아닙니다. 회사 Windows 11·DRM·SMB 환경의 장시간 시험은 최종 단계에 진행합니다.

## 고압축 Excel의 부가 customXml 판정 개선 (v1.3.29 이후)

- 고정된 `openpyxl 3.1.5`가 읽지 않는 Office 부가 요소 `customXml/itemN.xml`의 압축률이 높다는 이유만으로 정상 워크시트가 있는 XLSX 전체를 거부하는 사례를 수정했습니다. 부가 요소는 기존과 마찬가지로 결과 XLSX에 복사되지 않습니다.
- **워크시트·공유 문자열·통합문서 XML** 등의 압축률 검사와 ZIP 항목 개수, 중복, 압축 해제 전체 1GiB/각 XML 256MiB 한도는 유지합니다. 모든 고압축 Excel 문서를 허용하는 수정은 아닙니다.
- 실제 69MiB XML이 약 70KiB로 압축된 샘플에서 CSV `00123`과 수식 `=1+2`를 보존하는 병합을 확인했습니다. 사용자 원본과 기존 결과는 변경하지 않습니다.
- 회사 Windows 11·SMB·DRM의 **8시간 실사용 안정성 시험은 마지막 단계**로 남겨두었습니다.
